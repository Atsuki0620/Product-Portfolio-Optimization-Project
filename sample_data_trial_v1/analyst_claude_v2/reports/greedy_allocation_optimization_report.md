## 3. 貪欲配賦アルゴリズムの説明

### 3.1 アルゴリズムの基本原理

貪欲配賦アルゴリズムは、**各ステップで局所的に最良の選択を行う**ことで解を構築するヒューリスティック手法です。本プロジェクトでは、以下の優先度スコアを用いて配賦順序を決定します。

```
priority_score = unit_margin × margin_rate
```

- **unit_margin**: 単位粗利（円/本）= 販売単価 - 製造単価
- **margin_rate**: 粗利率 = unit_margin / 販売単価

このスコアは、「粗利額が大きく、かつ粗利率も高い」組合せを優先的に選択することを意図しています。

### 3.2 アルゴリズムのステップバイステップ説明

#### ステップ1: オプションテーブルの構築

過去3年間（2022-2024年度）の販売実績と生産実績を統合し、製品×拠点×セグメントの組合せごとに以下の指標を計算します。

1. **alloc_cap**（配賦上限）: 過去実績の平均販売数量
2. **unit_margin**（単位粗利）: 平均販売単価 - 平均製造単価
3. **margin_rate**（粗利率）: unit_margin / 平均販売単価
4. **avg_price**（平均販売単価）: 過去3年間の平均

**計算例**（P010, 拠点A, electronics）:
```python
# 過去3年間の販売実績から平均値を計算
avg_sales_qty = (7200 + 7100 + 6935) / 3 = 7078.33本
avg_sales_price = (91285 + 91233 + 91320) / 3 = ¥91,279/本

# 生産実績から平均製造単価を計算
avg_unit_cost = (52800 + 52630 + 52705) / 3 = ¥52,712/本

# 単位粗利と粗利率を計算
unit_margin = 91,279 - 52,712 = ¥38,567/本
margin_rate = 38,567 / 91,279 = 0.4225 (42.25%)

# 優先度スコアを計算
priority_score = 38,567 × 0.4225 = 16,294
```

このプロセスを全ての製品×拠点×セグメント組合せに対して実行し、オプションテーブルを構築します。

#### ステップ2: フィルタリング

オプションテーブルから、**unit_margin > 0**（粗利がプラス）の組合せのみを抽出します。これにより、赤字の組合せを配賦候補から除外します。

#### ステップ3: ソート（優先順位付け）

フィルタリングされたオプションを以下の順序でソートします：

1. **plant**（拠点）: 昇順（拠点Aから処理）
2. **priority_score**: 降順（高スコアから処理）
3. **margin_rate**: 降順（同スコアなら粗利率が高い方を優先）
4. **avg_price**: 降順（さらに同じなら高単価製品を優先）

この多段階ソートにより、拠点ごとに最も粗利が高い組合せから順に処理されます。

#### ステップ4: 初期化

配賦処理を開始する前に、以下の残量を初期化します：

```python
plant_remaining = {
    'A': 528,000 × 0.9 = 475,200本,
    'B': 528,000 × 0.9 = 475,200本
}

demand_remaining = {
    'automotive': 13,536本,
    'electronics': 8,937本,
    'construction': 9,751本,
    # ... 他のセグメント
}
```

#### ステップ5: 貪欲配賦ループ

ソートされたオプションを上位から順に1件ずつ処理します。各オプションに対して以下を実行します：

**ステップ5-1: 制約値の取得**

```python
option = (製品i, 拠点j, セグメントk)
alloc_cap = オプションの配賦上限（過去実績の平均）
demand_cap = demand_remaining[k]  # セグメントkの残需要
remaining_cap = plant_remaining[j]  # 拠点jの残キャパシティ
```

**ステップ5-2: 配賦数量の決定**

3つの制約値の最小値を取ります：

```python
alloc_qty = min(alloc_cap, demand_cap, remaining_cap)
```

この計算により、以下のいずれの制約も違反しない配賦数量が決定されます：
- 過去実績を超えない（市場での実現可能性）
- セグメント需要を超えない（需要制約）
- 拠点キャパシティを超えない（キャパシティ制約）

**ステップ5-3: 配賦レコードの作成**

`alloc_qty > 0`の場合、配賦レコードを作成します：

```python
allocation_record = {
    'product_code': i,
    'plant': j,
    'segment': k,
    'alloc_qty': alloc_qty,
    'unit_margin': unit_margin[i,j,k],
    'margin_rate': margin_rate[i,j,k],
    'alloc_margin': alloc_qty × unit_margin[i,j,k]
}
```

**ステップ5-4: 残量の更新**

配賦後、残量を更新します：

```python
plant_remaining[j] -= alloc_qty
demand_remaining[k] -= alloc_qty
```

**ステップ5-5: 終了条件の判定**

以下のいずれかが満たされた場合、ループを終了します：
- 全オプションを処理完了
- 全拠点のキャパシティが尽きた（`sum(plant_remaining) == 0`）
- 全セグメントの需要が満たされた（`sum(demand_remaining) == 0`）

#### ステップ6: サマリの作成

配賦結果から以下のサマリを作成します：

1. **拠点別サマリ**: 拠点ごとの配賦数量、粗利、キャパシティ使用率
2. **セグメント別サマリ**: セグメントごとの配賦数量、粗利、需要充足率
3. **全体サマリ**: 総配賦数量、総粗利、平均単位粗利

### 3.3 アルゴリズムの特徴

#### 長所

1. **計算速度が極めて速い**: O(n log n)の計算量（ソートが支配項）
2. **説明可能性が高い**: 「粗利×粗利率が高い順に配賦した」と明確に説明可能
3. **実装が容易**: 100行程度のPythonコードで実装可能
4. **実行可能解が必ず得られる**: 制約条件を満たす解が常に生成される

#### 短所

1. **最適性が保証されない**: 局所的に最良の選択をするため、全体最適とは限らない
2. **配賦順序への依存**: ソート基準により結果が変わる可能性
3. **制約追加が困難**: 新しい制約を追加する場合、アルゴリズムの修正が必要

## 6. 主要な知見（Key Findings）

### 6.1 粗利最大化の観点

#### 知見1: 高価格帯製品の圧倒的優位性

**発見**:
- 配賦された16組合せ中、**13組合せ（81%）がhigh価格帯製品**
- high価格帯製品の配賦率: 83%（12製品中10製品）
- low価格帯製品の配賦率: 25%（8製品中2製品）

**原因**:
- high価格帯製品は単位粗利が高い（平均¥30,000以上）
- priority_score = unit_margin × margin_rateの計算式で有利
- 粗利率も比較的高い（30-45%）

**経営インプリケーション**:
- **high価格帯製品への注力が粗利最大化の鍵**
- low価格帯製品は数量は多いが粗利貢献は限定的
- 製品開発・マーケティングリソースをhigh価格帯製品に集中すべき

#### 知見2: 製品集中度の高さ

**発見**:
- **Top3製品**（P014, P020, P010）が総粗利の**60.8%**を占める
- **Top5製品**で総粗利の**75.2%**を占める
- 特にP014が単独で**34.8%**を占める（極めて高い集中度）

**原因**:
- P014はfood_beverageセグメント（需要33.1%）を独占
- P020はautomotiveセグメント（需要16.4%）で高粗利を実現
- P010はelectronicsセグメント（需要10.8%）で最高単価を実現

**経営インプリケーション**:
- **重点製品の管理強化が必須**（品質、供給、価格）
- P014の製造トラブルは全体粗利の1/3を失うリスク
- ポートフォリオの多様化を検討すべき（リスク分散）

#### 知見3: セグメント間の収益性格差

**発見**:
- 最高単価セグメント（electronics）: ¥38,210/本
- 最低単価セグメント（consumer）: ¥10,155/本
- **格差は約3.8倍**

**原因**:
- electronicsセグメントは高付加価値製品（精密レーザー、クリーンルームコントローラ）
- consumerセグメントは汎用品（アクセルハウジング、低価格品）
- medicalセグメントも高単価（¥31,853）だが需要が小さい（6.5%）

**経営インプリケーション**:
- **electronics/medical/chemicalセグメントの需要拡大が粗利向上の鍵**
- consumerセグメントは数量は大きいが粗利貢献は限定的（3.7%）
- セグメント別のマーケティング戦略の差別化が必要

### 6.2 キャパシティ効率の観点

#### 知見4: 極めて低いキャパシティ使用率

**発見**:
- 拠点A使用率: **10.4%**（残余89.6%）
- 拠点B使用率: **7.0%**（残余93.0%）
- 全体使用率: **8.7%**（残余91.3%）

**原因**:
- **需要制約が支配的**（キャパシティ制約ではない）
- 総需要82,551本に対し、配賦上限950,400本（11.5倍のキャパシティ）
- セグメント別需要が少ない（最大でもfood_beverageの27,357本）

**経営インプリケーション**:
- **需要創出が最優先課題**（キャパシティは十分に余っている）
- 新市場開拓、新製品開発による需要拡大が可能
- キャパシティ投資は不要（既存設備で十分）
- 余剰キャパシティの活用方法を検討すべき（他社からのOEM受託など）

**発見**:

- 拠点A専用製品（P010, P015, P017, P018など）が高粗利

**経営インプリケーション**:

- セグメント別のリスクヘッジ戦略の策定

### 6.4 アルゴリズムの有効性

#### 知見8: 貪欲法の実用的有効性

#### 提言2: ポートフォリオ多様化【緊急度: 中】

**背景**: Top3製品で粗利の60.8%を占める高集中構造

4. low価格帯製品の見直し（配賦率25%と低い）

**期待効果**: リスク分散、粗利の安定化

#### 提言3: 需要創出戦略の策定【緊急度: 高】

**背景**: キャパシティ使用率8.7%（91.3%が余剰）

**期待効果**: キャパシティ活用率向上、粗利総額の拡大

#### 提言4: セグメント別戦略の差別化【緊急度: 中】

**期待効果**: 単価向上、粗利率改善

#### 提言5: MIPとの比較検証【緊急度: 中】

**背景**: 貪欲法は最適性が保証されない（Phase4でMIPを推奨）

**提言内容**:

**期待効果**: 粗利の更なる改善（推定¥68-227百万の追加粗利）

#### 提言6: リスクシナリオ分析の実施【緊急度: 中】

## 付録B: 用語集

| 用語 | 定義 |
|------|------|
| **貪欲配賦アルゴリズム** | 各ステップで局所的に最良の選択を行うヒューリスティック手法 |
| **priority_score** | unit_margin × margin_rateで計算される優先度スコア |
| **unit_margin** | 単位粗利（円/本）= 販売単価 - 製造単価 |
| **margin_rate** | 粗利率 = unit_margin / 販売単価 |
| **alloc_cap** | 配賦上限（過去実績の平均販売数量） |
| **alloc_qty** | 配賦数量（実際に配賦された数量） |
| **alloc_margin** | 配賦粗利 = alloc_qty × unit_margin |
| **配賦組合せ** | 製品×拠点×セグメントの特定の組合せ |
| **キャパシティ制約** | 拠点の生産能力上限（本プロジェクトでは各拠点475,200本/年） |
| **需要制約** | セグメント別の市場需要上限 |
| **販売実績上限制約** | 過去実績を超えない配賦量の制約（alloc_cap） |
