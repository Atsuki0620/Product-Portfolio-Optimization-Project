## 4.1 プロジェクトの本質と評価ポイント定義

### プロジェクトの本質

本プロジェクトは、製造業における**生産配賦最適化問題**です。以下の観点から本質を整理します。

#### 1. 目的（Objective）

**粗利総額の最大化**が主目的です。具体的には、限られた生産キャパシティを用いて、最も粗利が高くなる製品×拠点×セグメントの組み合わせを選択することです。

現行データでの目標水準：
- 総粗利: ¥2.27億（Base シナリオ）
- 配賦数量: 82,551本
- 平均単位粗利: ¥27,518

数理的には以下の目的関数で表現されます：

```
maximize Σ(alloc_qty[i,j,k] × unit_margin[i,j,k])
```

ただし、i=製品、j=拠点、k=セグメント

#### 2. 制約条件（Constraints）

本プロジェクトは複数の制約条件下での最適化問題です：

**キャパシティ制約（Capacity Constraints）**
- 拠点A: 528,000本（目標稼働率90%時: 475,200本）
- 拠点B: 528,000本（目標稼働率90%時: 475,200本）
- 合計: 1,056,000本（目標稼働率90%時: 950,400本）

数理的表現：
```
Σ_i,k alloc_qty[i,j,k] ≤ capacity[j] × utilization_target (for each plant j)
```

**需要制約（Demand Constraints）**
- セグメント別の需要上限が存在（segment_demand）
- 実データ例: automotive 30%, electronics 18%, construction 15%, etc.
- 各セグメントの配賦数量は需要を超えてはならない

数理的表現：
```
Σ_i,j alloc_qty[i,j,k] ≤ demand[k] (for each segment k)
```

**販売実績制約（Historical Sales Constraints）**
- 各製品×拠点×セグメントの組み合わせには過去実績に基づく配賦上限（alloc_cap）が存在
- これは市場での実現可能性を反映

数理的表現：
```
alloc_qty[i,j,k] ≤ alloc_cap[i,j,k]
```

**非負制約（Non-negativity Constraints）**
```
alloc_qty[i,j,k] ≥ 0
```

**整数制約（Integrality Constraints）**
- 配賦数量は整数値（本単位）
```
alloc_qty[i,j,k] ∈ ℤ≥0
```

#### 3. 意思決定の性質（Decision Characteristics）

**問題クラス**
- ナップザック問題の拡張版（Multiple Knapsack Problem with Multiple Constraints）
- 組合せ最適化問題
- NP困難（製品数・拠点数・セグメント数が増えると組み合わせ爆発）

**意思決定変数**
- 配賦数量 `alloc_qty[i,j,k]`（製品i、拠点j、セグメントkへの配賦量）
- 現状の問題規模: 20製品 × 2拠点 × 8セグメント = 最大320変数
  - ただし、製品ごとに allowed_plants、allowed_segments の制約があるため実際の変数数はより少ない
  - 実データでは約15個の配賦パターンが選択される

**意思決定のタイミング**
- 年度計画策定時（年1回）
- 四半期見直し時（年4回を想定）
- シナリオ分析時（需要変動・コスト変動・価格変動時の感度分析）

**意思決定の複雑性**
- 単一目的（粗利最大化）だが、複数制約あり
- 製品ごとに allowed_plants、allowed_segments が異なる
- 粗利は単位粗利だけでなく粗利率も考慮（priority_score = unit_margin × margin_rate）
- 将来的には、VIP顧客優先度、戦略的製品の重み付けなど多目的化の可能性あり

#### 4. データ特性（Data Characteristics）

**データ規模**
- 製品マスタ: 20製品（low価格帯13製品、high価格帯7製品）
- 拠点: 2拠点（A, B）
- セグメント: 8セグメント
- 年度: 3年度（2022, 2023, 2024）
- 販売実績レコード数: 約200-300行/年度
- 生産実績レコード数: 約60-80行/年度

**入力データの特性**
- margin_matrix（粗利マトリクス）
  - 製品×拠点×セグメント×年度の組み合わせごとに粗利情報を保持
  - 欠損値: 実績がない組み合わせは存在しない（fillna(0)処理済み）
  - 外れ値: 販売単価が現実的範囲（low: ¥10k-30k, high: ¥60k-100k）に調整済み

- segment_demand（セグメント別需要）
  - 8セグメント × 需要数量
  - 理論構成比との差異が3%ポイント以内に調整済み
  - 総需要: 約950,000本

- CapacityConfig（キャパシティ設定）
  - 拠点別の総キャパシティと目標稼働率（90%）
  - 固定値として設定（将来的には設備投資による変動可能性あり）

**データ更新頻度**
- マスタデータ: 年1回更新（新製品追加、廃番処理）
- 販売実績: 月次蓄積（年度末に年度データとして確定）
- 生産実績: 月次蓄積（年度末に年度データとして確定）
- 需要予測: 四半期ごとに更新

**データ品質**
- 精度: 過去実績ベースのため高精度
- 完全性: 必須項目は全て埋まっている
- 一貫性: Phase2で単価・コスト・粗利率の整合性を確保
- 時系列性: 年度成長が適切に反映（year_drift効果）

#### 5. 運用要件（Operational Requirements）

**計算時間**
- 年度計画策定: 数分以内が望ましい（担当者が待てる時間）
- 四半期見直し: 1分以内が理想
- シナリオ分析: 7シナリオを同時実行して10分以内
- 現行の貪欲アルゴリズム: 数秒で完了（十分に高速）

**説明可能性（Explainability）**
- 経営層への説明が必要
  - なぜこの製品がこの拠点に配賦されたのか
  - なぜこのセグメントが優先されたのか
  - 代替案との比較（What-if分析）
- 現行の貪欲アルゴリズムは「単位粗利×粗利率が高い順」というシンプルなロジックで説明可能
- ブラックボックスな手法（例: 複雑なメタヒューリスティック）は説明が困難

**保守性（Maintainability）**
- データサイエンティストではなく、製造部門の担当者が運用
- Pythonコードの理解が可能なレベル（高度な数学知識は不要）
- アルゴリズムの修正が容易であること（制約追加、目的関数変更など）

**拡張性（Extensibility）**
- 将来的な拡張要件:
  - 製品数: 20 → 50程度への拡大
  - 拠点数: 2 → 5程度への拡大（海外拠点追加）
  - セグメント数: 8 → 10-12程度への拡大
  - 新しい制約: VIP顧客優先度、戦略的製品の最低配賦数量、環境制約（CO2排出量）など
  - 多目的最適化: 粗利だけでなく、顧客満足度、リードタイム、在庫回転率なども考慮

**ロバスト性（Robustness）**
- 需要予測の誤差: ±10%程度の変動に対応（DemandPlus10/DemandMinus10シナリオで検証済み）
- コスト変動: ±5%程度の変動に対応（CostPlus5/CostMinus5シナリオで検証済み）
- 価格変動: ±5%程度の変動に対応（PricePlus5/PriceMinus5シナリオで検証済み）
- データ欠損への耐性: fillna(0)で対応、ゼロ除算防止済み
- 境界条件への対応: alloc_qty ≤ 0 のケースは配賦スキップ

### 評価ポイントの定義と重み付け

本プロジェクトにおいて、代替アルゴリズムを評価する際の評価軸を以下の通り定義します。各評価軸には、本プロジェクトの特性を踏まえた重要度を重み付けします（合計100%）。

#### 評価ポイント一覧

| 評価軸 | 重み | 説明 |
|--------|------|------|
| 1. 最適性 | **30%** | 理論最適解にどれだけ近いか（粗利総額の最大化度合い） |
| 2. 説明可能性 | **25%** | 経営層・現場への説明のしやすさ、納得感 |
| 3. 計算速度 | **15%** | 実行時間（年度計画・四半期見直しに耐えうるか） |
| 4. 実装容易性 | **10%** | コーディング・保守・修正の容易さ |
| 5. 制約柔軟性 | **10%** | 新しい制約を追加しやすいか |
| 6. スケーラビリティ | **5%** | 製品数・拠点数が増えた時の対応力 |
| 7. ロバスト性 | **5%** | データの揺れ・外れ値への耐性 |
| **合計** | **100%** | |

#### 各評価軸の詳細

**1. 最適性（Optimality）: 30%**

本プロジェクトの最重要評価軸です。粗利総額の最大化がビジネス目標であるため、理論最適解にどれだけ近い解が得られるかが最も重要です。

評価基準:
- S評価（100点）: 数理的に最適解が保証される（例: 線形計画法による厳密解）
- A評価（85点）: 最適解の95%以上の解が得られることが理論的・実験的に示される
- B評価（70点）: 最適解の90%以上の解が得られる
- C評価（50点）: 最適解の80%以上の解が得られる
- D評価（30点）: 最適解の80%未満、または解の質が保証されない

測定方法:
- 厳密解法（MIP）と比較して、粗利総額の達成率を算出
- 現行の貪欲アルゴリズムをベースライン（100%）として、改善率を測定
- 複数のランダムシードでの平均値を使用（再現性確認）

**2. 説明可能性（Explainability）: 25%**

経営層への報告、現場担当者の納得感、監査対応などで極めて重要です。本プロジェクトでは、「なぜこの配賦になったのか」を明確に説明できることが必須です。

評価基準:
- S評価（100点）: ルールベースで完全に説明可能（例: 貪欲法の「粗利が高い順」）
- A評価（85点）: アルゴリズムのロジックが明確で、非専門家にも理解可能（例: 線形計画法の目的関数・制約式）
- B評価（70点）: アルゴリズムの概要は説明できるが、細部は専門知識が必要（例: 局所探索法）
- C評価（50点）: アルゴリズムの説明は困難だが、結果の妥当性は示せる（例: メタヒューリスティック）
- D評価（30点）: ブラックボックス、説明が困難（例: 深層学習）

評価観点:
- 経営層への説明容易性（プレゼン資料で1ページで説明できるか）
- 現場担当者の理解度（Pythonコードを読んで理解できるか）
- 結果の再現性（同じ入力で同じ結果が得られるか）
- What-if分析の容易性（パラメータ変更時の挙動予測）

**3. 計算速度（Computational Speed）: 15%**

年度計画策定や四半期見直しで実用的な時間内に結果が得られることが重要です。ただし、最適性と説明可能性に比べれば優先度は低めです。

評価基準:
- S評価（100点）: 1秒以内（リアルタイム分析可能）
- A評価（85点）: 10秒以内（インタラクティブ分析可能）
- B評価（70点）: 1分以内（四半期見直しに使用可能）
- C評価（50点）: 10分以内（年度計画策定に使用可能）
- D評価（30点）: 10分超（実用性に疑問）

測定方法:
- 現行データ（20製品×2拠点×8セグメント×3年度）での実行時間
- スケーリングテスト（製品数2倍、拠点数2倍時の実行時間）

**4. 実装容易性（Implementation Ease）: 10%**

現場の担当者が保守・修正できることが重要です。外部ライブラリへの依存が少なく、標準的なPythonコードで実装できることが望ましいです。

評価基準:
- S評価（100点）: 標準ライブラリ + pandas + numpy のみで実装可能、100行以内
- A評価（85点）: 一般的な最適化ライブラリ（scipy.optimize, PuLP等）を使用、200行以内
- B評価（70点）: 専門ライブラリ（Gurobi, CPLEX等）が必要、ライセンス費用あり
- C評価（50点）: 複雑なライブラリ、複数の依存関係、500行以上
- D評価（30点）: 外部システム連携、特殊な環境が必要

評価観点:
- コード行数（少ないほど保守が容易）
- 外部依存ライブラリの数と入手容易性
- アルゴリズムの実装難易度（デバッグのしやすさ）

**5. 制約柔軟性（Constraint Flexibility）: 10%**

将来的に新しい制約（VIP顧客優先度、戦略的製品の最低配賦量、CO2排出量制約など）を追加する可能性があるため、制約の追加・変更が容易であることが重要です。

評価基準:
- S評価（100点）: 制約を宣言的に追加可能（例: 線形計画法の制約式追加）
- A評価（85点）: コードの一部修正で制約追加可能（例: ペナルティ関数の追加）
- B評価（70点）: アルゴリズムの一部を書き換えて制約追加可能
- C評価（50点）: アルゴリズムの大幅な修正が必要
- D評価（30点）: 制約追加が極めて困難（アルゴリズムの根本的な書き換えが必要）

評価観点:
- 新制約追加時のコード変更範囲
- 制約追加後の計算時間への影響
- 多目的最適化への拡張可能性

**6. スケーラビリティ（Scalability）: 5%**

製品数・拠点数が増えた時の対応力です。現状では20製品×2拠点ですが、将来的に50製品×5拠点程度への拡大を想定します。

評価基準:
- S評価（100点）: 問題規模が10倍になっても計算時間が10倍以内（線形スケーリング）
- A評価（85点）: 計算時間が問題規模のO(n log n)でスケール
- B評価（70点）: 計算時間が問題規模のO(n²)でスケール
- C評価（50点）: 計算時間が問題規模のO(n³)でスケール
- D評価（30点）: 指数的スケーリング、大規模問題には適用不可

評価観点:
- 計算量の理論的解析（時間計算量・空間計算量）
- スケーリングテストの実測値

**7. ロバスト性（Robustness）: 5%**

需要予測誤差、価格変動、コスト変動などのデータの揺れに対して、安定した結果が得られることが重要です。ただし、Phase2でデータ品質を改善済みのため、優先度は低めです。

評価基準:
- S評価（100点）: データの±20%変動でも結果が大きく変わらない
- A評価（85点）: データの±10%変動でも安定
- B評価（70点）: データの±5%変動でも安定
- C評価（50点）: データの微小変動で結果が大きく変わる
- D評価（30点）: 外れ値や欠損値で計算エラーが発生

評価観点:
- シナリオ分析での結果の安定性
- 外れ値への耐性
- パラメータ感度（ハイパーパラメータの調整が必要な場合、その影響度）

### 評価フレームワークの使用方法

上記の7つの評価軸に基づき、各代替手法を以下の手順で評価します：

1. **各評価軸でS/A/B/C/D評価を実施**（100点/85点/70点/50点/30点）
2. **重み付けスコアを計算**: 評価点 × 重み
3. **総合スコアを算出**: 各評価軸の重み付けスコアの合計（100点満点）
4. **総合評価を決定**:
   - S評価（90点以上）: 最優先で推奨
   - A評価（80点以上）: 強く推奨
   - B評価（70点以上）: 推奨
   - C評価（60点以上）: 条件付きで推奨
   - D評価（60点未満）: 推奨しない

次のセクションでは、この評価フレームワークを用いて、各代替手法を網羅的にリサーチし、詳細評価を実施します。

## 4.2 代替手法の網羅的リサーチ

本プロジェクトに適用可能な代替手法を、以下の5つのカテゴリに分類して網羅的にリサーチします。各手法について、概要・特徴・適用例・本プロジェクトへの適用可能性を整理します。

### カテゴリ1: 数理最適化（Mathematical Optimization）

数理計画法とも呼ばれ、目的関数と制約条件を数式で表現し、厳密解または準最適解を求める手法群です。最適性が理論的に保証される点が最大の特徴です。

#### 1-1. 線形計画法（Linear Programming, LP）

**概要**
目的関数と制約条件がすべて線形式で表現できる最適化問題を解く手法です。シンプレックス法や内点法などの効率的なアルゴリズムが確立されており、大規模問題にも適用可能です。

**特徴**
- 目的関数が線形: `maximize c^T x`
- 制約条件が線形: `Ax ≤ b, x ≥ 0`
- 連続変数を扱う（整数制約は扱えない）
- 最適解が必ず得られる（実行可能解が存在する場合）
- 計算時間は問題規模に対して多項式時間
- 双対性理論により感度分析が可能

**適用例**
- 生産計画（連続量の配分）
- 輸送問題（最小コスト流問題）
- ブレンディング問題（原料配合最適化）
- ポートフォリオ最適化（連続的な資産配分）

**本プロジェクトへの適用可能性**
- ✅ 目的関数は線形（粗利総額 = Σ unit_margin × alloc_qty）
- ✅ 制約条件は線形（キャパシティ制約、需要制約）
- ❌ **整数制約が必要**（配賦数量は整数値）
- 評価: **変数を連続変数として緩和すれば適用可能だが、整数制約が必要なため単独では不十分**

#### 1-2. 混合整数計画法（Mixed Integer Programming, MIP）

**概要**
線形計画法に整数変数を加えた手法です。一部または全ての変数に整数制約を課すことができます。分枝限定法（Branch and Bound）や分枝カット法（Branch and Cut）により、厳密解または近似解を求めます。

**特徴**
- 目的関数と制約条件は線形
- 変数に整数制約を課すことができる
- NP困難問題だが、商用ソルバー（Gurobi, CPLEX）の性能が高い
- 最適性ギャップを指定して近似解を高速に求めることも可能
- 大規模問題（数千〜数万変数）でも実用的な時間で解ける

**適用例**
- 生産スケジューリング（整数個のジョブ割り当て）
- 設備配置問題（工場・倉庫の開設/閉鎖の0-1決定）
- ナップザック問題（整数個のアイテム選択）
- カッティングストック問題（材料の切り出し最適化）
- 人員配置問題（整数人のシフト割り当て）

**本プロジェクトへの適用可能性**
- ✅ 目的関数は線形（粗利総額の最大化）
- ✅ 制約条件は線形（キャパシティ、需要、非負制約）
- ✅ 整数変数を扱える（alloc_qty ∈ ℤ≥0）
- ✅ 問題規模が適度（変数数〜320個程度）
- ✅ 厳密解が得られる
- 評価: **本プロジェクトに最も適した手法の一つ。理論最適解が保証される**

**数式モデル例**
```
目的関数:
  maximize Σ_i,j,k (unit_margin[i,j,k] × alloc_qty[i,j,k])

制約条件:
  Σ_i,k alloc_qty[i,j,k] ≤ capacity[j] × 0.9  ∀j (キャパシティ制約)
  Σ_i,j alloc_qty[i,j,k] ≤ demand[k]  ∀k (需要制約)
  alloc_qty[i,j,k] ≤ alloc_cap[i,j,k]  ∀i,j,k (販売実績上限)
  alloc_qty[i,j,k] ≥ 0  ∀i,j,k (非負制約)
  alloc_qty[i,j,k] ∈ ℤ  ∀i,j,k (整数制約)
```

#### 1-3. 非線形計画法（Nonlinear Programming, NLP）

**概要**
目的関数または制約条件に非線形項を含む最適化問題を解く手法です。勾配法、ニュートン法、内点法などが用いられます。

**特徴**
- 目的関数や制約条件に非線形項（二次式、指数関数、対数関数など）を含む
- 局所最適解に陥る可能性あり（凸最適化でない場合）
- 計算時間は問題の性質に依存（凸問題なら効率的）
- 非凸問題は大域最適解の保証が困難

**適用例**
- ポートフォリオ最適化（分散最小化、シャープレシオ最大化）
- 電力系統最適化（二次損失を含む）
- 化学プロセス最適化（反応速度が非線形）
- 機械学習のパラメータ最適化（損失関数が非線形）

**本プロジェクトへの適用可能性**
- ❌ 目的関数は線形（非線形化する必然性がない）
- ❌ 制約条件も線形
- ⚠️ 粗利率を考慮する場合、`priority_score = unit_margin × margin_rate`を目的関数に組み込むと非線形になる可能性あり
- 評価: **本プロジェクトでは線形計画法で十分。非線形化する必要性が低い**

### カテゴリ2: ヒューリスティック（Heuristics）

厳密解は保証されないが、実用的な時間で良い解を求める経験則に基づく手法群です。シンプルで実装が容易、計算速度が高速という特徴があります。

#### 2-1. 貪欲法（Greedy Algorithm）← **現行手法**

**概要**
各ステップで局所的に最良の選択を行い、解を構築していく手法です。本プロジェクトでは、`priority_score = unit_margin × margin_rate`が高い順に配賦する貪欲法を採用しています。

**特徴**
- アルゴリズムがシンプル（ソート → 順次配賦）
- 計算時間がO(n log n)（ソートが支配項）
- 最適解は保証されない（近視眼的な選択）
- 説明可能性が極めて高い
- 実装が容易（100行以内）

**適用例**
- ナップザック問題の近似解法（単位重量あたり価値が高い順に詰める）
- タスクスケジューリング（納期が早い順、処理時間が短い順）
- 最小全域木（Kruskalのアルゴリズム、Primのアルゴリズム）
- ハフマン符号化（出現頻度が高い文字から符号化）

**本プロジェクトでの実績**
- 配賦数量: 82,551本
- 総粗利: ¥2,271,684,422
- 計算時間: 数秒
- 説明可能性: 極めて高い（「粗利×粗利率が高い順」で説明可能）

**本プロジェクトへの適用可能性**
- ✅ 既に採用済み
- ✅ 実用上十分な解が得られている
- ⚠️ 最適性は保証されない（MIPと比較して改善余地がある可能性）
- 評価: **ベースライン手法として優秀。ただし、更なる粗利改善の余地を探るべき**

#### 2-2. 局所探索法（Local Search / Hill Climbing）

**概要**
初期解から出発し、近傍の解を探索して改善を繰り返す手法です。これ以上改善できなくなった時点（局所最適解）で終了します。

**特徴**
- 初期解が必要（ランダム生成、または貪欲法で構築）
- 近傍の定義が重要（例: 1つの配賦を別の製品に変更、2つの配賦を交換）
- 局所最適解に陥る可能性が高い
- 計算時間は反復回数に依存
- 説明可能性は中程度（「初期解から改善を繰り返した」と説明）

**適用例**
- 巡回セールスマン問題（2-opt法、3-opt法）
- グラフ彩色問題
- 施設配置問題
- ジョブショップスケジューリング

**本プロジェクトへの適用可能性**
- ✅ 貪欲法の解を初期解として改善可能
- ⚠️ 近傍の定義が難しい（どの配賦をどう変更するか）
- ⚠️ 局所最適解に陥りやすい
- ⚠️ 貪欲法より計算時間が長い
- 評価: **貪欲法の改善手法として有効。ただし、大幅な改善は期待しにくい**

**近傍の定義例**
1. **Swap近傍**: 2つの配賦（i1, j1, k1）と（i2, j2, k2）の数量を交換
2. **Insert近傍**: ある配賦の数量を減らし、別の配賦の数量を増やす
3. **Remove-Insert近傍**: ある配賦を削除し、別の配賦を追加

#### 2-3. タブーサーチ（Tabu Search）

**概要**
局所探索法の拡張版で、直近の探索履歴（タブーリスト）を記憶し、同じ解への逆戻りを防ぐ手法です。局所最適解を脱出できるため、より広範囲の探索が可能です。

**特徴**
- タブーリストで探索履歴を管理（通常、直近10〜100ステップ）
- 局所最適解を一時的に受け入れる（悪化する移動も許容）
- 多様化戦略・集中化戦略でバランスを取る
- 計算時間は反復回数×近傍探索時間
- 説明可能性は中程度

**適用例**
- 車両配送計画（VRP）
- 生産スケジューリング
- グラフ彩色問題
- 施設配置問題

**本プロジェクトへの適用可能性**
- ✅ 局所探索よりも広範囲を探索可能
- ⚠️ パラメータ調整が必要（タブーリストサイズ、反復回数）
- ⚠️ 実装が複雑化（タブーリスト管理）
- ⚠️ 説明可能性が低下
- 評価: **局所探索より高品質な解が期待できるが、実装コストと説明可能性がトレードオフ**

#### 2-4. 焼きなまし法（Simulated Annealing, SA）

**概要**
金属の焼きなまし過程を模倣した手法です。温度パラメータを徐々に下げながら、確率的に悪化する移動も受け入れることで、局所最適解を脱出します。

**特徴**
- 温度パラメータTで悪化を受け入れる確率を制御
- 受理確率: `exp(-Δf / T)`（Δf: 目的関数の悪化量）
- 温度を徐々に下げる（冷却スケジュール）
- 局所最適解を脱出しやすい
- 確率的アルゴリズムのため、実行ごとに結果が異なる

**適用例**
- 巡回セールスマン問題
- グラフ分割問題
- VLSIレイアウト設計
- タンパク質折りたたみ問題

**本プロジェクトへの適用可能性**
- ✅ 局所最適解を脱出可能
- ⚠️ パラメータ調整が難しい（初期温度、冷却率、反復回数）
- ⚠️ 確率的手法のため再現性が低い
- ⚠️ 説明可能性が低い（「確率的に探索した」では経営層に説明困難）
- 評価: **高品質な解が期待できるが、説明可能性と再現性の問題で本プロジェクトには不向き**

### カテゴリ3: メタヒューリスティック（Metaheuristics）

自然界の現象や生物の行動を模倣した最適化手法群です。大規模問題や複雑な制約条件に対応できますが、パラメータ調整が必要で、説明可能性が低いという課題があります。

#### 3-1. 遺伝的アルゴリズム（Genetic Algorithm, GA）

**概要**
生物の進化過程（選択・交叉・突然変異）を模倣した最適化手法です。複数の解（個体）を集団として保持し、世代交代を繰り返すことで解を改善します。

**特徴**
- 集団ベースの探索（通常、50〜200個体）
- 交叉（Crossover）: 2つの親個体から子個体を生成
- 突然変異（Mutation）: ランダムな変更で多様性を維持
- 選択（Selection）: 適合度が高い個体を優先的に次世代に残す
- パラメータ: 集団サイズ、交叉率、突然変異率、世代数
- 確率的手法のため再現性が低い

**適用例**
- ナップザック問題
- スケジューリング問題
- ニューラルネットワークの構造探索
- 多目的最適化（Paretoフロンティア探索）

**本プロジェクトへの適用可能性**
- ⚠️ 遺伝子コーディングが複雑（配賦パターンをどう表現するか）
- ⚠️ 交叉操作で実行可能解を保つことが困難（キャパシティ制約違反の可能性）
- ⚠️ パラメータ調整が必要
- ⚠️ 計算時間が長い（世代数×集団サイズ×評価回数）
- ⚠️ 説明可能性が極めて低い
- 評価: **本プロジェクトには不向き。制約条件が多く、実行可能解の維持が困難**

#### 3-2. 粒子群最適化（Particle Swarm Optimization, PSO）

**概要**
鳥の群れや魚の群れの行動を模倣した最適化手法です。各粒子が探索空間を移動し、自分の最良位置と群れの最良位置に引き寄せられながら解を探索します。

**特徴**
- 連続変数の最適化に適している
- 粒子の位置と速度を更新
- パラメータ: 粒子数、慣性重み、学習係数
- 微分情報が不要
- 多峰性関数の最適化に有効

**適用例**
- ニューラルネットワークの重み最適化
- 関数最適化（ベンチマーク問題）
- アンテナ設計
- ロボット制御

**本プロジェクトへの適用可能性**
- ❌ 連続変数向けの手法（整数変数は扱いにくい）
- ❌ 制約条件の扱いが困難
- ❌ 本プロジェクトは離散的な配賦問題のため適さない
- 評価: **本プロジェクトには不適。整数計画問題には向かない**

#### 3-3. アリコロニー最適化（Ant Colony Optimization, ACO）

**概要**
アリが餌を探す際のフェロモン軌跡を模倣した最適化手法です。主に組合せ最適化問題（巡回セールスマン問題など）に適用されます。

**特徴**
- グラフ上の経路探索問題に適している
- フェロモン量を更新しながら解を構築
- 確率的に経路を選択（フェロモン量が多い経路を選びやすい）
- パラメータ: アリの数、フェロモン蒸発率、重み係数

**適用例**
- 巡回セールスマン問題（TSP）
- 車両配送計画（VRP）
- ネットワークルーティング
- ジョブショップスケジューリング

**本プロジェクトへの適用可能性**
- ⚠️ 配賦問題をグラフ問題として表現する必要あり
- ⚠️ 問題の性質に合わない（経路探索ではない）
- ⚠️ パラメータ調整が困難
- ⚠️ 説明可能性が低い
- 評価: **本プロジェクトには不向き。経路探索問題向けの手法**

### カテゴリ4: 機械学習アプローチ（Machine Learning）

データから学習し、予測や意思決定を行う手法群です。最適化問題を学習問題として捉え直すアプローチです。

#### 4-1. 強化学習（Reinforcement Learning, RL）

**概要**
エージェントが環境と相互作用しながら、報酬を最大化する方策を学習する手法です。配賦問題を逐次意思決定問題として捉え、最適な配賦戦略を学習します。

**特徴**
- 状態（State）: 現在の配賦状況、残キャパシティ、残需要
- 行動（Action）: 次に配賦する製品×拠点×セグメントの選択
- 報酬（Reward）: 配賦により得られる粗利
- 方策（Policy）: 状態から行動への写像（学習対象）
- 代表的手法: Q学習、DQN、PPO、A3C

**適用例**
- ゲーム（囲碁、将棋、ビデオゲーム）
- ロボット制御
- 広告配信最適化
- リソース割り当て問題

**本プロジェクトへの適用可能性**
- ⚠️ 学習データが必要（多数の配賦シナリオと結果）
- ⚠️ 学習時間が長い（数千〜数万エピソード）
- ⚠️ 説明可能性が極めて低い（ブラックボックス）
- ⚠️ 最適性の保証がない
- ⚠️ 制約条件の扱いが難しい
- 評価: **本プロジェクトには不向き。学習コストが高く、説明可能性が低い**

#### 4-2. 教師あり学習（Supervised Learning）

**概要**
過去の配賦結果を教師データとして、配賦パターンを予測するモデルを構築します。

**特徴**
- 入力: 製品特性、拠点特性、セグメント特性、需要、キャパシティ
- 出力: 配賦数量の予測
- 手法: 線形回帰、決定木、ランダムフォレスト、勾配ブースティング、ニューラルネットワーク

**本プロジェクトへの適用可能性**
- ❌ 最適化問題を予測問題に置き換えることになる（本質的な目的とずれる）
- ❌ 過去データに依存するため、新しい状況への対応が困難
- ❌ 制約条件を満たす保証がない
- 評価: **本プロジェクトには不適。最適化問題を予測問題として扱うのは不自然**

### カテゴリ5: その他の手法（Others）

数理最適化とヒューリスティックの中間的な手法、または特定の問題構造に特化した手法です。

#### 5-1. 制約プログラミング（Constraint Programming, CP）

**概要**
制約条件を宣言的に記述し、制約伝播と探索により実行可能解を求める手法です。スケジューリング問題や割り当て問題に強みがあります。

**特徴**
- 制約条件を自然言語に近い形で記述可能
- 制約伝播により探索空間を削減
- 目的関数の最適化よりも実行可能解の発見に重点
- ツール: Google OR-Tools, MiniZinc, Gecode

**適用例**
- スケジューリング問題（ジョブショップ、シフト作成）
- 配置問題（座席配置、リソース割り当て）
- パズル（数独、N-Queen問題）

**本プロジェクトへの適用可能性**
- ✅ 制約条件の記述が容易
- ⚠️ 目的関数の最適化はMIPに劣る
- ⚠️ 実行可能解は見つかるが、最適解の保証が弱い
- 評価: **制約が複雑な場合に有効。ただし、本プロジェクトの制約は線形なのでMIPで十分**

#### 5-2. 動的計画法（Dynamic Programming, DP）

**概要**
問題を部分問題に分解し、小さい問題から順に解いていく手法です。最適部分構造を持つ問題に適用可能です。

**特徴**
- 部分問題の最適解を保存（メモ化）し、重複計算を避ける
- 最適性原理が成り立つ問題に適用可能
- 計算量はO(状態数 × 遷移数)
- 最適解が保証される

**適用例**
- ナップザック問題（0-1ナップザック）
- 最短経路問題
- 編集距離
- 動的ロット決定問題

**本プロジェクトへの適用可能性**
- ⚠️ 状態空間が大きい（製品×拠点×セグメント×残キャパシティ×残需要）
- ⚠️ 多次元ナップザック問題は動的計画法で解くのが困難
- ⚠️ メモリ消費が膨大
- 評価: **本プロジェクトには不向き。状態空間が大きすぎる**

#### 5-3. 分枝限定法（Branch and Bound, B&B）

**概要**
MIPソルバーの中核アルゴリズムです。探索木を構築し、枝刈り（Bound）により不要な探索を省略します。

**特徴**
- LP緩和により下界（または上界）を計算
- 最適解が含まれない枝を刈る
- 最適解が保証される
- MIPソルバー（Gurobi, CPLEX）に組み込み済み

**本プロジェクトへの適用可能性**
- ✅ MIPソルバーを使えば自動的に適用される
- ⚠️ 単独で実装するのは困難
- 評価: **MIPソルバー内部で使用される。単独実装は不要**

#### 5-4. 列生成法（Column Generation）

**概要**
大規模線形計画問題を解く手法です。変数（列）を動的に生成しながら最適解を求めます。カッティングストック問題や車両配送計画に適用されます。

**特徴**
- 変数が膨大な場合に有効
- マスター問題とサブ問題を反復的に解く
- 最適解が保証される（整数制約なしの場合）

**本プロジェクトへの適用可能性**
- ❌ 変数数が適度（〜320個）のため不要
- ❌ 列生成のメリットが小さい
- 評価: **本プロジェクトには不要。問題規模が小さいため**

### リサーチまとめ

以下の手法群をリサーチしました：

**カテゴリ1: 数理最適化**
1. 線形計画法（LP）: 整数制約がないため単独では不十分
2. **混合整数計画法（MIP）**: ✅ 最有力候補。厳密解が得られる
3. 非線形計画法（NLP）: 本プロジェクトでは不要

**カテゴリ2: ヒューリスティック**
1. **貪欲法（Greedy）**: ✅ 現行手法。ベースラインとして優秀
2. **局所探索法（Local Search）**: ✅ 貪欲法の改善手法として有効
3. タブーサーチ（Tabu Search）: 局所探索より高品質だが実装が複雑
4. 焼きなまし法（SA）: 説明可能性が低い

**カテゴリ3: メタヒューリスティック**
1. 遺伝的アルゴリズム（GA）: 制約条件の扱いが困難

### 手法1: 混合整数計画法（Mixed Integer Programming, MIP）

#### 概要

混合整数計画法（MIP）は、線形計画法に整数変数を追加した数理最適化手法です。目的関数と制約条件を線形式で記述し、変数の一部または全てに整数制約を課すことができます。本プロジェクトのような生産配賦最適化問題は、MIPの典型的な適用対象です。配賦数量という整数値を決定変数とし、粗利総額を最大化するという目的を数式で表現します。

商用ソルバー（Gurobi、CPLEX）やオープンソースソルバー（PuLP、Google OR-Tools）を使用することで、問題を数式として定義するだけで、分枝限定法（Branch and Bound）や分枝カット法（Branch and Cut）といった高度なアルゴリズムが自動的に適用され、厳密解または指定した最適性ギャップ内の近似解が得られます。

#### 特徴

MIPの最大の特徴は、**理論最適解が保証される**点です。問題が実行可能である限り、与えられた目的関数と制約条件の下で数理的に最良の解を求めることができます。本プロジェクトの場合、目的関数は粗利総額の最大化（`Σ unit_margin × alloc_qty`）、制約条件はキャパシティ制約、需要制約、販売実績上限制約、非負制約、整数制約であり、全て線形式で表現可能です。

現代のMIPソルバーは非常に高性能で、数千から数万の変数を持つ問題でも実用的な時間で解くことができます。本プロジェクトの問題規模は、製品20個×拠点2個×セグメント8個×年度3年度で最大約320変数程度（実際には allowed_plants、allowed_segments の制約により変数数はより少ない）であり、MIPソルバーにとっては小〜中規模の問題です。

また、MIPは**制約の追加・変更が容易**という特徴があります。将来的にVIP顧客優先度や戦略的製品の最低配賦量といった新しい制約を追加する場合でも、数式として制約条件を追加するだけで対応できます。多目的最適化への拡張も可能で、例えば粗利と顧客満足度の両方を考慮したい場合、重み付け和として目的関数を定義することで対応できます。

#### メリット

**1. 最適性の保証**
MIPの最大のメリットは、厳密解が得られる点です。貪欲法などのヒューリスティックでは「おそらく良い解」しか得られませんが、MIPでは「これ以上良い解は存在しない」という保証が得られます。経営層に対して「数理的に最適な配賦計画」として説明でき、意思決定の根拠として強力です。

**2. 制約条件の柔軟な追加**
新しいビジネス要件が追加された場合でも、制約式を追加するだけで対応できます。例えば、「製品Xは最低1000本配賦する」「セグメントYへの配賦は全体の10%以上」「拠点間の配賦比率は6:4以内」といった複雑な制約も、線形不等式として表現できれば容易に組み込めます。

**3. 感度分析が可能**
MIPソルバーは双対変数（Shadow Price）を提供するため、制約条件の変化が目的関数に与える影響を定量的に分析できます。例えば、「拠点Aのキャパシティを1000本増やすと粗利がいくら増えるか」といった感度分析が可能です。これは設備投資の意思決定に有用です。

**4. スケーラビリティ**
現代のMIPソルバーは高度に最適化されており、並列計算も活用されます。問題規模が2倍になっても、計算時間が2倍程度で済むことが多く、将来的な製品数・拠点数の拡大にも対応可能です。

**5. 実装が比較的容易**
PuLPやGoogle OR-Toolsなどのライブラリを使えば、Pythonで数式を記述するだけでMIPソルバーを利用できます。分枝限定法などの複雑なアルゴリズムを自分で実装する必要はありません。

#### デメリット

**1. 説明可能性の課題**
MIPの解は数理的に最適ですが、「なぜこの配賦になったのか」を直感的に説明するのは困難です。貪欲法の「粗利が高い順に配賦した」という説明に比べ、「制約条件を満たしつつ目的関数を最大化した結果」という説明は抽象的です。特に、制約がぎりぎりのケースでは、なぜこの製品が選ばれてあの製品が選ばれなかったのかを説明するのが難しい場合があります。

**2. ソルバーへの依存**
高性能な商用ソルバー（Gurobi、CPLEX）はライセンス費用が高額です（年間数十万〜数百万円）。オープンソースソルバー（CBC、GLPK）は無料ですが、性能が劣ります。ただし、Google OR-Toolsは無料で高性能なため、本プロジェクトではこれを使用すれば問題ありません。

**3. 計算時間の不確実性**
MIPはNP困難問題のため、問題の構造によっては計算時間が長くなる可能性があります。ただし、本プロジェクトの問題規模（〜320変数）では、数秒〜数十秒で解けることが期待されます。万が一計算時間が長い場合は、最適性ギャップを指定する（例: 「最適解の99%以上の解が見つかれば終了」）ことで計算時間を短縮できます。

**4. 非線形目的関数への対応困難**
MIPは線形問題に限定されます。もし将来的に非線形の目的関数（例: リスク最小化のための分散の最小化）を扱いたい場合は、二次計画法（QP）や非線形計画法（NLP）への拡張が必要です。ただし、本プロジェクトの目的関数は線形なので現時点では問題ありません。

### 手法2: 貪欲法（Greedy Algorithm）← **現行手法**

#### 概要

貪欲法は、各ステップで局所的に最良の選択を行うことで解を構築するヒューリスティック手法です。本プロジェクトでは、`priority_score = unit_margin × margin_rate`が高い順に製品×拠点×セグメントの組み合わせを選択し、キャパシティと需要の範囲内で配賦数量を決定します。この手法は実装がシンプルで、計算時間が極めて短く、説明可能性が高いという特徴があります。

アルゴリズムの流れは以下の通りです：
1. 製品×拠点×セグメントの全組み合わせについて、priority_scoreを計算
2. priority_scoreが高い順にソート
3. 上位から順に、残キャパシティと残需要の範囲内で配賦
4. キャパシティまたは需要が尽きるまで繰り返し

このアルゴリズムは一度のパスで解を構築するため、計算時間がO(n log n)（ソートの計算量）で済み、極めて高速です。

#### 特徴

貪欲法の最大の特徴は、**シンプルさと説明可能性の高さ**です。アルゴリズムのロジックが明快で、「単位粗利×粗利率が高い順に配賦した」という一言で説明できます。経営層や現場担当者にとって理解しやすく、納得感が得られやすい手法です。

また、**実装が容易**である点も大きな特徴です。本プロジェクトの現行実装は約100行のPythonコードで、外部ライブラリへの依存もpandasとnumpyのみです。保守・修正が容易で、製造部門の担当者でも理解・修正が可能です。

一方、貪欲法は**最適性が保証されない**という根本的な制約があります。各ステップで局所的に最良の選択をするため、全体として最適な解が得られるとは限りません。特に、キャパシティ制約が厳しい場合、先に配賦した製品が後で配賦する製品の選択肢を狭めてしまう可能性があります（ブロッキング問題）。

#### メリット

**1. 極めて高い説明可能性**
貪欲法の最大のメリットは、誰にでも理解できる説明が可能な点です。「粗利が高く、かつ粗利率も高い製品から優先的に配賦した」という説明は、経営層にとって直感的で納得感があります。個々の配賦についても、「この製品はpriority_scoreが○○点で上位だったため選ばれた」と明確に説明できます。

**2. 実装が極めて容易**
アルゴリズムがシンプルなため、100行以内のコードで実装できます。外部の最適化ライブラリも不要で、標準的なPython環境（pandas、numpy）だけで動作します。デバッグも容易で、バグが発生しにくいコードです。

**3. 計算速度が極めて速い**
ソート処理（O(n log n)）が支配的な計算量であり、現行データでは数秒で完了します。リアルタイムでの分析が可能で、パラメータを変更しながらインタラクティブに解を探索できます。

**4. 保守性が高い**
コードがシンプルなため、将来的な修正や拡張が容易です。例えば、priority_scoreの計算式を変更したい場合、1行のコード修正で対応できます。製造部門の担当者が自分でメンテナンスできる点も大きなメリットです。

**5. ロバスト性が高い**
データに外れ値や欠損があっても、アルゴリズムが破綻することはありません。制約条件を満たす実行可能解が必ず得られます（キャパシティと需要の範囲内で配賦するため）。

#### デメリット

**1. 最適性が保証されない**
貪欲法の最大のデメリットは、理論最適解が得られる保証がない点です。近視眼的な選択のため、全体として粗利が最大化されない可能性があります。特に、以下のようなケースで最適解からの乖離が大きくなる可能性があります：

- キャパシティ制約が厳しい場合: 先に配賦した製品が後の選択肢を狭める（フラグメンテーション）
- 製品間の相互依存がある場合: ある製品を配賦することで別の製品が配賦できなくなる
- 複数の制約がタイトにバインドする場合: キャパシティと需要の両方が限界に近い

実際に貪欲法がMIPの最適解と比べてどれだけ劣るかは、問題の構造とデータに依存します。本プロジェクトでは、現行の貪欲法が総粗利¥2.27億を達成していますが、MIPで解くとこれより高い粗利が得られる可能性があります。

**2. 制約の追加が難しい**
新しい制約（VIP顧客優先度、戦略的製品の最低配賦量など）を追加する場合、アルゴリズムの構造を変更する必要があります。例えば、「製品Xは最低1000本配賦する」という制約を追加したい場合、配賦順序を変更したり、事前に一部を予約配賦したりする必要があり、アルゴリズムが複雑化します。

**3. 配賦順序への依存**
貪欲法は、どの順序で配賦するかによって結果が変わります。現行の実装では`priority_score`降順でソートしていますが、この順序が本当に最良かは保証されません。ソート基準を変更すると（例: `unit_margin`のみで降順、`margin_rate`のみで降順）、異なる解が得られます。

**4. 多目的最適化への拡張が困難**
粗利だけでなく、顧客満足度やリードタイムなど複数の目的を同時に考慮したい場合、貪欲法では対応が困難です。priority_scoreに複数の指標を組み込むことは可能ですが、重み付けの設定が恣意的になります。

- **リソース配分**: 優先度が高いリクエストから順にリソースを割り当てる
- **在庫配分**: 需要が多い拠点から順に在庫を配分する
- **ナップザック問題の近似解**: 単位重量あたり価値が高いアイテムから詰める

### 手法3: 局所探索法（Local Search）+ 貪欲法のハイブリッド

#### 概要

局所探索法は、貪欲法で構築した初期解を出発点として、近傍の解を探索しながら改善を繰り返す手法です。貪欲法単独では最適性が保証されませんが、局所探索を組み合わせることで、貪欲法の解をさらに改善できる可能性があります。このハイブリッドアプローチは、貪欲法の高速性と説明可能性を維持しつつ、解の品質を向上させることを狙います。

アルゴリズムの流れは以下の通りです：
1. 貪欲法で初期解を構築（高速・高品質な初期解）
2. 初期解から近傍解を生成（Swap、Insert、Remove-Insertなど）
3. 近傍解の中で粗利が改善するものがあれば採用
4. これ以上改善できなくなるまで繰り返し

近傍の定義が重要です。本プロジェクトでは、以下のような近傍が考えられます：
- **Swap近傍**: 2つの配賦（i1, j1, k1）と（i2, j2, k2）の数量を一部交換
- **Insert近傍**: ある配賦の数量を減らし、別の配賦の数量を増やす
- **Remove-Insert近傍**: ある配賦を削除し、別の配賦を追加

#### 特徴

局所探索+貪欲法のハイブリッドは、貪欲法の解を改善しつつ、MIPほどの計算時間はかからないという**中間的な特徴**を持ちます。貪欲法の初期解が既に高品質なため、改善の余地は限定的かもしれませんが、局所的な調整により数%の粗利改善が期待できます。

説明可能性は貪欲法単独に比べるとやや低下します。「貪欲法で初期解を作り、その後で局所的に改善した」という説明は可能ですが、「なぜこの改善が行われたのか」を個々のステップで説明するのは困難です。

#### メリット

**1. 貪欲法の解を改善可能**
局所探索により、貪欲法の解をさらに改善できる可能性があります。特に、貪欲法で見逃した有望な配賦パターンを発見できる場合があります。

**2. MIPより高速**
MIPは厳密解を求めますが、計算時間が長くなる可能性があります。局所探索は反復回数を制限できるため、計算時間を制御しやすいです。

**3. 実装が比較的容易**
貪欲法のコードに近傍探索のロジックを追加するだけなので、実装難易度は中程度です。100〜200行程度のコードで実装できます。

**4. 説明可能性は中程度**
貪欲法単独よりは説明が複雑になりますが、「貪欲法の解を微調整した」という説明は可能です。

#### デメリット

**1. 改善幅が限定的**
貪欲法の初期解が既に高品質な場合、局所探索での改善幅は数%程度に留まる可能性があります。大幅な改善を期待するのは難しいです。

**2. 局所最適解に陥る**
局所探索は、近傍に改善解がなくなった時点で終了するため、局所最適解に陥ります。大域最適解（MIPの解）には到達できない可能性があります。

**3. 近傍の定義が難しい**
どのような近傍を定義するかで結果が大きく変わります。近傍が小さすぎると改善が進まず、大きすぎると計算時間が長くなります。最適な近傍の設計には試行錯誤が必要です。

**4. 計算時間が不確実**
反復回数が事前に予測できないため、計算時間が不確実です。最悪の場合、多数の反復が必要になる可能性があります。

#### 本プロジェクトにおける7軸評価

**評価1: 最適性（重み30%）**: **B評価（75点）** - 貪欲法より改善するが、MIPの厳密解には劣る
**評価2: 説明可能性（重み25%）**: **B評価（70点）** - 貪欲法より説明が複雑化
**評価3: 計算速度（重み15%）**: **A評価（85点）** - 数十秒程度で完了する見込み
**評価4: 実装容易性（重み10%）**: **B評価（70点）** - 貪欲法より複雑だがMIPより容易
**評価5: 制約柔軟性（重み10%）**: **C評価（50点）** - 制約追加は貪欲法と同様に困難
**評価6: スケーラビリティ（重み5%）**: **B評価（70点）** - 反復回数が問題規模に依存
**評価7: ロバスト性（重み5%）**: **A評価（85点）** - 貪欲法と同様に安定

**総合スコア**: 30×75% + 25×70% + 15×85% + 10×70% + 10×50% + 5×70% + 5×85% = **72.5点**

**総合評価: B評価**

局所探索+貪欲法のハイブリッドは、貪欲法の解を改善する中間的な手法として有効です。ただし、改善幅が限定的であり、MIPの厳密解には劣ります。説明可能性も貪欲法単独に比べて低下します。

### 手法4: 線形計画法（Linear Programming, LP）- 整数緩和版

#### 概要

線形計画法（LP）は、配賦数量を連続変数として扱う最適化手法です。本プロジェクトでは整数制約（配賦数量は整数値）が必要ですが、整数制約を緩和して連続変数として扱うことで、LPで解くことができます。LPはMIPよりも計算時間が短く、多項式時間で厳密解が得られます。

得られた連続値の解を丸め処理（四捨五入、切り捨て、切り上げ）することで整数解を得ます。ただし、丸め処理により制約違反が発生する可能性があるため、後処理で調整が必要です。

#### 特徴

LPの最大の特徴は、**計算速度が極めて速い**点です。シンプレックス法や内点法により、大規模問題でも多項式時間で解けます。本プロジェクトの問題規模であれば、数秒以内に解が得られます。

また、**双対性理論により感度分析が可能**です。各制約条件の影響度（Shadow Price）を定量的に評価でき、設備投資や需要開拓の優先順位を決定する際に有用です。

一方、**整数制約が扱えない**という根本的な制約があります。丸め処理により整数解を得ることは可能ですが、最適性が保証されません。また、丸め処理で制約違反が発生する可能性があります。

#### メリット

**1. 計算速度が極めて速い**
LPは多項式時間で解けるため、MIPよりもさらに高速です。大規模問題でも数秒で解けます。

**2. 感度分析が容易**
双対変数により、各制約条件の影響度を定量的に評価できます。「拠点Aのキャパシティを1000本増やすと粗利がいくら増えるか」といった分析が可能です。

**3. 実装が容易**
PuLPやscipy.optimizeなどのライブラリを使えば、MIPと同様にPythonで数式を記述するだけで解けます。

#### デメリット

**1. 整数制約が扱えない**
配賦数量が小数値になるため、丸め処理が必要です。丸め処理により最適性が失われ、制約違反が発生する可能性もあります。

**2. 丸め誤差の影響**
配賦数量が大きい場合（数千〜数万本）は丸め誤差の影響は小さいですが、配賦数量が小さい場合（数十〜数百本）は丸め誤差の影響が大きくなります。

**3. 制約違反のリスク**
丸め処理により、キャパシティ制約や需要制約を超過する可能性があります。後処理で調整が必要です。

#### 本プロジェクトにおける7軸評価

**評価1: 最適性（重み30%）**: **B評価（75点）** - 連続緩和の最適解は得られるが、丸め処理で劣化
**評価2: 説明可能性（重み25%）**: **A評価（85点）** - MIPと同様に数式モデルで説明可能
**評価3: 計算速度（重み15%）**: **S評価（100点）** - 数秒以内に解ける
**評価4: 実装容易性（重み10%）**: **A評価（85点）** - MIPと同様に容易
**評価5: 制約柔軟性（重み10%）**: **S評価（100点）** - MIPと同様に容易
**評価6: スケーラビリティ（重み5%）**: **S評価（100点）** - 大規模問題にも対応可能
**評価7: ロバスト性（重み5%）**: **B評価（70点）** - 丸め処理で不安定になる可能性

**総合スコア**: 30×75% + 25×85% + 15×100% + 10×85% + 10×100% + 5×100% + 5×70% = **84.75点**

**総合評価: A評価**

LPは計算速度が極めて速く、感度分析も可能ですが、整数制約が扱えない点がネックです。丸め処理により実用的な整数解を得ることは可能ですが、MIPの厳密解には劣ります。

### 手法5: 制約プログラミング（Constraint Programming, CP）

#### 概要

制約プログラミング（CP）は、制約条件を宣言的に記述し、制約伝播と探索により実行可能解を求める手法です。MIPと似ていますが、制約の表現力が高く、論理制約（if-then、all-different）や非線形制約も扱えます。Google OR-ToolsのCP-SATソルバーは高性能で、MIPソルバーと同等以上の性能を発揮する場合があります。

#### 特徴

CPの特徴は、**制約の表現力が高い**点です。MIPでは線形制約しか扱えませんが、CPでは論理制約や非線形制約も自然に記述できます。例えば、「製品Aを配賦する場合は製品Bも配賦しなければならない」といった条件依存の制約を容易に表現できます。

また、**制約伝播により探索空間を削減**するため、特定の問題構造では極めて高速に解けます。スケジューリング問題や配置問題では、MIPよりもCPの方が効率的な場合が多いです。

#### メリット

**1. 制約の表現力が高い**
論理制約、条件依存の制約、非線形制約などを自然に記述できます。将来的に複雑な制約を追加したい場合に有利です。

**2. 特定の問題構造では高速**
スケジューリング問題や配置問題では、MIPよりも効率的に解ける場合があります。

**3. 実装が比較的容易**
Google OR-ToolsのCP-SATソルバーを使えば、Pythonで制約を宣言的に記述できます。

#### デメリット

**1. 目的関数の最適化はMIPに劣る**
CPは実行可能解の発見に強みがありますが、目的関数の最適化（粗利最大化）ではMIPに劣る場合があります。

**2. 説明可能性は中程度**
制約条件は宣言的に記述できますが、解がどのように求められたかを説明するのは難しいです。

**3. 本プロジェクトの制約は線形**
本プロジェクトの制約条件は全て線形なので、CPの高い表現力を活かす場面が少ないです。

### 手法6: タブーサーチ（Tabu Search）

#### 概要

タブーサーチは、局所探索法の拡張版で、直近の探索履歴（タブーリスト）を記憶し、同じ解への逆戻りを防ぐ手法です。局所最適解を一時的に受け入れることで、より広範囲の探索が可能になります。貪欲法よりも高品質な解が期待できますが、実装が複雑化し、説明可能性が低下します。

#### 特徴

タブーサーチは、局所探索よりも**広範囲の探索が可能**です。タブーリストにより直近の探索を禁止することで、同じ局所最適解に陥ることを防ぎます。また、多様化戦略（長時間探索していない領域を探索）と集中化戦略（有望な領域を重点的に探索）を組み合わせることで、解の品質を向上させます。

一方、**パラメータ調整が必要**です。タブーリストのサイズ、反復回数、多様化・集中化の切り替えタイミングなどを適切に設定する必要があり、試行錯誤が必要です。

#### メリット

**1. 局所探索より高品質な解**
局所最適解を脱出できるため、局所探索よりも高品質な解が期待できます。貪欲法と比較しても、5〜10%程度の改善が期待できる可能性があります。

**2. MIPより高速（場合による）**
反復回数を制限すれば、MIPより高速に解を得ることができます。

#### デメリット

**1. 実装が複雑**
タブーリスト管理、多様化・集中化戦略の実装など、アルゴリズムが複雑化します。200〜300行以上のコードが必要になる可能性があります。

**3. 説明可能性が低い**
「タブーサーチで探索した」という説明では、経営層や現場担当者の理解を得にくいです。個々の配賦の理由を説明するのも困難です。

**4. 再現性が低い**
初期解や探索順序に依存するため、同じ入力でも異なる結果が得られる可能性があります。

**評価4: 実装容易性（重み10%）**: **C評価（50点）** - 実装が複雑
**評価5: 制約柔軟性（重み10%）**: **C評価（50点）** - 制約追加は困難

### 推奨Top3と選定理由

本プロジェクトに推奨する手法Top3と、それぞれの採用場面を以下に示します。

#### 第1推奨: MIP（混合整数計画法）- 本番運用の主力手法として推奨

**選定理由**

MIPは、本プロジェクトの目的（粗利総額の最大化）と制約条件（キャパシティ、需要、整数変数）に最も適した手法です。総合スコア93.5点（S評価）で全手法中1位であり、特に以下の点で優れています：

1. **理論最適解が保証される（最適性S評価）**: 貪欲法では得られない「数理的に最適な配賦」が得られます。経営層に対して「これ以上良い解は存在しない」という強力な根拠を提示できます。

2. **制約の柔軟な追加が可能（制約柔軟性S評価）**: 将来的にVIP顧客優先度、戦略的製品の最低配賦量、CO2排出量制約などを追加する場合でも、線形不等式として制約を追加するだけで対応できます。多目的最適化への拡張も容易です。

3. **実用的な計算時間（計算速度A評価）**: 本プロジェクトの問題規模（〜320変数）であれば、Google OR-Toolsなどの高性能ソルバーを使用して数秒〜数十秒で解けると予想されます。四半期見直しや年度計画策定に十分使用できる速度です。

4. **感度分析が可能**: 双対変数（Shadow Price）により、「拠点Aのキャパシティを1000本増やすと粗利がいくら増えるか」といった定量的な分析が可能です。設備投資の意思決定に有用です。

**採用場面**
- 年度計画策定（年1回）
- 四半期見直し（年4回）
- シナリオ分析（需要変動・コスト変動・価格変動時の感度分析）
- 設備投資計画時の感度分析

**実装方法**
```python
# Google OR-Toolsを使用したMIP実装例（疑似コード）
from ortools.linear_solver import pywraplp

# ソルバーを初期化
solver = pywraplp.Solver.CreateSolver('SCIP')  # またはGLOP, CBC

# 変数を定義: alloc_qty[i,j,k] （整数変数）
alloc_qty = {}
for i in products:
    for j in plants:
        for k in segments:
            alloc_qty[i,j,k] = solver.IntVar(0, alloc_cap[i,j,k], f'alloc_{i}_{j}_{k}')

# 目的関数: 粗利総額の最大化
objective = solver.Objective()
for i in products:
    for j in plants:
        for k in segments:
            objective.SetCoefficient(alloc_qty[i,j,k], unit_margin[i,j,k])
objective.SetMaximization()

# 制約条件1: キャパシティ制約
for j in plants:
    solver.Add(solver.Sum([alloc_qty[i,j,k] for i in products for k in segments])
               <= capacity[j] * 0.9)

# 制約条件2: 需要制約
for k in segments:
    solver.Add(solver.Sum([alloc_qty[i,j,k] for i in products for j in plants])
               <= demand[k])

# 求解
status = solver.Solve()
if status == pywraplp.Solver.OPTIMAL:
    print(f'最適粗利: ¥{solver.Objective().Value():,.0f}')
```

**期待される効果**
- 貪欲法と比較して、粗利総額の改善（改善幅は実装後に検証が必要だが、数%〜10%程度の改善が期待できる）
- 制約条件の追加・変更が容易になり、将来的なビジネス要件変更に柔軟に対応可能
- 設備投資や需要開拓の優先順位を定量的に評価可能（感度分析）

#### 第2推奨: Greedy（貪欲法）- ベースライン手法として継続使用を推奨

**選定理由**

貪欲法は現行手法であり、総合スコア81.25点（A評価）で全手法中4位です。MIPに比べて最適性は劣りますが、以下の点で極めて優れています：

1. **説明可能性が極めて高い（S評価）**: 「粗利×粗利率が高い順に配賦した」という説明は、経営層・現場担当者の誰にでも理解できます。個々の配賦の理由も明確に説明できます。この点は、他のどの手法よりも優れており、意思決定の透明性が求められる場面で重要です。

2. **計算速度が極めて速い（S評価）**: 現行データでは数秒で完了し、リアルタイム分析が可能です。パラメータを変更しながらインタラクティブに解を探索できます。

3. **実装が極めて容易（S評価）**: 100行以内のコードで実装でき、外部ライブラリへの依存も最小限（pandas、numpyのみ）です。製造部門の担当者でも理解・保守が可能です。

4. **実績がある**: 既に本プロジェクトで運用されており、総粗利¥2.27億、配賦数量82,551本という実用上十分な解が得られています。

**採用場面**
- MIPとの比較検証（ベースライン）
- 迅速な意思決定が必要な場面（緊急時の配賦計画変更）
- 経営層への初期説明（MIPの結果と比較して説明）
- 大規模問題でMIPの計算時間が長い場合の代替手法

**役割**
- **ベースライン手法**: MIPの結果と比較して、粗利の改善幅を評価
- **フォールバック手法**: MIPの計算時間が長い場合や、システム障害時の代替手法
- **教育用途**: 新任担当者への配賦アルゴリズムの説明

**期待される効果**
- MIPとの比較により、現行手法の改善余地を定量的に評価可能
- 説明可能性の高さにより、経営層・現場担当者の納得感を維持
- 迅速な意思決定が可能

#### 第3推奨: LP（線形計画法・整数緩和版）- 感度分析・初期検討用途として推奨

**選定理由**

LPは、整数制約を緩和して連続変数として扱うことで、極めて高速に解を得ることができます。総合スコア84.75点（A評価）で全手法中3位であり、以下の点で優れています：

1. **計算速度が極めて速い（S評価）**: 多項式時間で解けるため、MIPよりもさらに高速です。大規模問題でも数秒で解けます。

2. **感度分析が容易**: 双対変数（Shadow Price）により、各制約条件の影響度を定量的に評価できます。設備投資の優先順位決定に有用です。

3. **制約柔軟性が高い（S評価）**: MIPと同様に、制約を線形不等式として宣言的に追加できます。

**注意点**
- 整数制約が扱えないため、丸め処理が必要です。丸め処理により最適性が失われ、制約違反が発生する可能性もあります。
- **本番運用の主力手法としては推奨しません**。あくまで感度分析や初期検討用途です。

**採用場面**
- 設備投資計画時の感度分析（「拠点Aのキャパシティを1000本増やすと粗利がいくら増えるか」）
- 需要開拓の優先順位決定（「セグメントXの需要を1000本増やすと粗利がいくら増えるか」）
- 大規模シナリオ分析（数百パターンのシナリオを高速に評価）
- 初期検討フェーズ（問題の構造を理解するための試行錯誤）

**役割**
- **感度分析ツール**: 制約条件の変化が粗利に与える影響を定量的に評価
- **初期検討ツール**: 問題構造の理解、実行可能性の確認
- **大規模シナリオ分析ツール**: 多数のシナリオを高速に評価

**実装方法**
```python
# scipy.optimizeを使用したLP実装例（疑似コード）
from scipy.optimize import linprog

# 目的関数の係数（最大化問題なので符号を反転）
c = [-unit_margin[i,j,k] for i,j,k in options]

# 制約条件の係数行列と右辺
A_ub = []  # 不等式制約の係数行列
b_ub = []  # 不等式制約の右辺

# キャパシティ制約
for j in plants:
    row = [1 if option[1]==j else 0 for option in options]
    A_ub.append(row)
    b_ub.append(capacity[j] * 0.9)

# 需要制約
for k in segments:
    row = [1 if option[2]==k else 0 for option in options]
    A_ub.append(row)
    b_ub.append(demand[k])

# 求解
result = linprog(c, A_ub=A_ub, b_ub=b_ub, bounds=(0, None))

# 双対変数（Shadow Price）を取得
shadow_prices = result.slack
```

**期待される効果**
- 設備投資の優先順位を定量的に評価可能（Shadow Priceによる感度分析）
- 需要開拓の優先順位を定量的に評価可能

### 推奨しない手法と理由

**Local Search（局所探索法）**: 総合スコア72.5点（B評価）
- 貪欲法の解を改善できるが、改善幅が限定的（数%程度）
- MIPで厳密解が得られるため、局所探索を採用するメリットが小さい
- 説明可能性が貪欲法より低下する
- **結論**: MIPまたは貪欲法を優先し、局所探索は不採用

**Constraint Programming（制約プログラミング）**: 総合スコア87.25点（A評価）
- 制約の表現力が高いが、本プロジェクトの制約は全て線形なので強みを活かせない
- MIPで十分対応可能
- **結論**: 将来的に論理制約や非線形制約を追加する場合に再検討。現時点ではMIPを優先

**Tabu Search（タブーサーチ）**: 総合スコア62.0点（C評価）
- 実装が複雑、説明可能性が低い、再現性が低い
- MIPで厳密解が得られるため、タブーサーチを採用するメリットがない
- **結論**: 不採用
